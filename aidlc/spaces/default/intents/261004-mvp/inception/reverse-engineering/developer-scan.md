### Build System

- **Type: none (runtime).** The prototype is `file://`-openable vanilla HTML + CSS + ES5 JS. No bundler, no transpiler, no minifier. `prototype/index.html` declares the script-tag load order explicitly (lines 62–73): `i18n.js → data.js → ui.js → screen-map.js (mockup set) → screens-core.js → screens-orders.js → screens-catalog.js → screens-money.js → screens-system.js → screens-journeys.js → app.js`. The comment at line 61 calls out the ordering invariant ("load order matters: tokens → helpers → data → components → screens → router"). The presentation chrome (`#chrome`) — Device / Language / Role / AI / Flows toggles — is rendered in `index.html` lines 17–52 and wired by `app.js wireChrome()` (line 221–266).
- **Build config files present:** none at `prototype/`. **No** `package.json`, **no** `tsconfig.json`, **no** `vite.config.*`, **no** `webpack.config.*`, **no** `.eslintrc.*`, **no** `.prettierrc.*`, **no** `.editorconfig`, **no** CI config (`.github/`, `.gitlab-ci.yml`, etc.). The prototype carries no CI of its own.
- **Build dependencies (package → package relationships):** effectively none at runtime. At test time, `prototype/tests/package.json` is the only `package.json` in scope: it depends on `jsdom` and `ws` only, and its `node_modules/` is gitignored. **Every screen module depends on `i18n.js` → `data.js` → `ui.js`** (which declares `App.I`, `App.STATUS`, `App.NAV`, `App.ui`, `App.esc`, role helpers, money-level helpers), and on **all earlier screens' module registering their own `App.screens.*` and `App.actions.*` before `app.js` boots**. The boot order is also the dependency graph — there are no `import` statements; every file is loaded via `<script src=…>` and writes to the shared `window.App` global inside an IIFE.
- **External dependency from `index.html`:** Google Fonts CDN — `Hind Siliguri` (weights 400/500/600/700) and `Noto Serif Bengali` (weights 500/600/700) loaded via `https://fonts.googleapis.com`. Without internet, Bangla copy still renders via the system Bengali fallback declared in `tokens.css` (`--font-ui: 'Hind Siliguri', 'Noto Sans Bengali', …`; `--font-display: 'Noto Serif Bengali', …`).
- **Cross-file imports in JS:** there are no `import` statements. All inter-module wiring is via the `window.App` global namespace declared in `i18n.js` line 6, extended by every subsequent file with `window.App = window.App || {};` at the top.

### Test Coverage

- **Test directories:** `prototype/tests/` only. There is no test directory at the repo root.
- **Test frameworks:** eight bespoke Node CJS harnesses, no Jest / Mocha / Vitest. Each harness is a self-contained executable (`node smoke.js`, etc.) registered as an npm script in `prototype/tests/package.json` line 6.
- **Coverage config:** none. No `nyc`, no `c8`, no Istanbul. The harnesses assert structural and arithmetic properties rather than statement coverage.
- **What is asserted:**
  - `smoke.js` — no runtime errors across every route × device × language × Role, and every click from a freshly rendered state. ~16,000 render combinations (76 routes × 2 devices × 2 AI × 2 langs × 5 Roles) plus ~thousands of clicks (`clicks exercised` printed at the end).
  - `auth-zero.js` — signin / register / recovery / reset / replaced / setup / empty-dashboard / invitation states; negative-asserts the source for OTP, forced setup wizard steps (`setup/catalogue`, `setup/team`, `setup/done`), and legacy `staff`/`packer` Role keys.
  - `truth.js` — six sections: (1) `econ()` internal-exactness (profit = net − cogs − courierFee − codFee − pack − returnLoss, no cost or loss negative), (2) every dashboard headline is the sum of its rows, (3) gated Roles (`sales`, `inventory`) reach no money figure on **any** route and are offered no destination into a money screen, (3b) Role model matches PRD §6.2 for audit / capture / ask, (4) no Latin digit in any Bangla screen (with allow-list for record ids / phones / filenames / urls / version / iso dates), (5) every assistant answer declares a legal Recognition Basis + sane completeness + distinct prose, (6) settlement panel figure follows a disposition.
  - `flows.js` — assistant route→answer / route→refuse / route→gated, voice dictation, three-level variant matrix, quick-add grid, paste-flow variant picker, parsed-item-scope, completeness sheet.
  - `classes.js` — every class that lands in the DOM has a CSS rule, and every `is-…` / `has-…` modifier is joined to a base class in a selector (the `.lang-card.is-on`-vs-bare-token blind spot was the reason this exists).
  - `contrast.js` — arithmetic WCAG luminance ratios computed off `tokens.css`: text tones ≥ 4.5 on every paper background, ink-toned text ≥ 4.5 on every ink, every −600 hue ≥ 3.0 (large figures), every −700 hue ≥ 4.5 (small text), `line-control` ≥ 3.0 (control border floor).   - `story-coverage.js` — 76 stories in `epics.md` ↔ 76 designs in `SMARTBIZ_SCREEN_MAP` ↔ 76 addressable frames each carrying title/surface/state/proofs/primary action.
  - `shot.js` — screenshots of states jsdom cannot reproduce (real type rendering, layout). Outputs to `prototype/tests/shots/` (gitignored).
  - `measure.js` — `getBoundingClientRect` + `getComputedStyle` of any selectors over CDP.

### Architecture Decisions Visible in the Prototype

1. **Bangla-first i18n.** `App.lang` defaults to `'bn'` (i18n.js line 13). Every piece of UI copy is `L(bn, en)`. Bangla digits render via `bnDigits` everywhere except an explicit allow-list (phone numbers, record IDs, filenames, URLs, ISO dates, version strings — codified in `truth.js` line 26–35). Architect must preserve this in production: a Bangla-first product that renders `1,250` in Latin digits is "only half translated" (i18n.js line 1–4).
2. **Token-based design system.** `tokens.css` defines the full vocabulary (ink/canvas/text/text-on-ink ramps, six hue ramps green/brass/amber/red/teal/violet with semantic `--realized`/`--earned`/`--incomplete`, type/space/radius/elevation/motion/frame). `app.css` and `screens.css` consume them. `contrast.js` validates them. `prefers-reduced-motion` is honoured (tokens.css line 148–150).
3. **Status vocabulary + recognition basis.** `App.STATUS` (ui.js line 111–122) declares 9 order states with Bangla/English copy and a colour tone. `App.RECOGNITION` (data.js line 412) declares `EARNED = {delivered, partial, settled}` and `REALIZED = {settled}`. Every money figure in the product states its basis (`basisPill` ui.js line 132–135). The Completeness Indicator (`completeness()` ui.js line 137–147) states how much of the figure is included. **This is the product's thesis** — "remove it and the numbers become opinions" (ui.js line 130–131). Architect: do not collapse these.
4. **Role-driven capability matrix.** Three orthogonal flags — `money` (sees profit), `price` (sees selling price), `cost` (sees purchase cost) — encoded as `App.ROLES[role].money: 'full' | 'price' | 'cost'` (data.js line 14–20), plus an explicit `roles` array on screens that need a Role list rather than a money level (audit at `screens-system.js` line 44, invitations at `screens-core.js` line 175, capture at `screens-orders.js` line 99). `App.canReach(route)` (ui.js line 94–102) consults all three; screens that are Role-adaptive self-gate the figures they would otherwise leak (`dailySummary` line 496–500 is the canonical example). The PRD §6.2 matrix is encoded as `CAN_AUDIT` / `CAN_CAPTURE` / `CAN_ASK` in `truth.js` line 147–155 and re-asserted by absence over every route, *not* by the presence of a lock on one route. The architect must preserve all three layers.
5. **Hash router, no history library.** `parse` / `go` / `back` / `render` (app.js line 22–96) plus a 40-entry in-memory `App.history` (line 19). `boot()` re-routes to `#/splash` if no hash (line 416). The chrome dropdown syncs to the route via `syncChrome()` (line 192–218) with a hand-coded nearest-match scorer. There is no `pushState`, no SPA framework — the app **re-renders by replacing `app.innerHTML`** on every navigation (line 81, 76). This is the explicit prototype choice ("opens straight from the filesystem with no server", app.js line 1–3).
6. **Sidebar + bottom-nav (tabbar) surface both supported.** `ui.js shell()` (line 261–271) swaps between `sidebar()` (desktop) and `statusbar()` + `tabbar()` (phone) based on `App.device`. Tabs are 5 (Home / Orders / FAB / Stock / COD-or-Customers-or-Products depending on Role). The FAB is hidden unless `App.canCreateOrders()`. The sidebar has 6 groups (Work / Catalogue / Money / Insight / System) with badge counts driven by `App.summary().lowStock` / `unsettled` / `App.orders.length` etc.
7. **State management: a single `App.state` bag.** All UI filters and buffers (`orderFilter`, `custBand`, `auditFilter`, `paste`, `parsed`, `insight`, `voice`, `draftExpense`, `stepTime` placements). No Redux / Zustand / MobX — a plain mutable object. Tests reach into it directly (`boot.js` line 60–69).
8. **Component model: string-template HTML + a small set of helper functions.** No virtual DOM, no JSX, no template engine. Every screen is a function `(args) → {title, body, …}` returning an HTML string. Helpers in `ui.js` (`field`, `toggleRow`, `statusChip`, `basisPill`, `completeness`, `moneyEl`, `riskChip`, `barRow`, `provenance`, `emptyState`, `roleLock`, `sheet`/`openSheet`/`closeSheet`, `toast`) keep the patterns consistent. `App.esc()` (ui.js line 71–75) is the only sanitiser.
9. **Sheet + toast for ephemeral UI.** Sheets stack in `App.sheetStack` (ui.js line 274–296); the router closes every open sheet on navigation (app.js line 52). Toasts live in a host div created/destroyed by the router (app.js line 59–61, 88–92; the comment at line 57–58 explains the detach-then-re-attach dance — "a toast raised just before a navigation has to survive the render that follows it").
10. **Action dispatch via a single registry.** `App.actions[name](arg, el, e)` (app.js line 301). Built-ins `back`, `close-sheet`, `noop`, `toggle`, `press`, `pick` (line 280–299) handle the common patterns; everything else falls through to the registry or a warn-toast if unknown. Naming convention: kebab-case verb (`order-filter`, `paste-parse`, `pick-variant`, `completeness-why`, `disposition-save`).
11. **The paste parser is real, not staged.** `parseMessage` (screens-orders.js line 141–262) anchors on a 11-digit phone number, normalizes Bangla digits to Latin, finds name/address relative to the phone, then **segments the message at natural item boundaries** so each product reads only its own words (the comment at line 206–210 documents a bug it prevented: "the sample's pink dupatta came out black, because the kurti's কালো appeared later in the text and the last match won"). The architect must preserve this if order capture remains in scope.
12. **Test isolation by *what each harness is blind to*.** The README in `prototype/tests/` line 8: "eight harnesses, kept separate because **each one is blind to what the others catch**. That is the whole design; collapsing them into one runner would lose the property." The mutual-blindness table (lines 10–19) is the documentation of this design. Architect must preserve this when planning the production test strategy.

## Handoff Summary

**Intent-relevant finding.** The SmartBiz BD "prototype" at `prototype/` is a 4-file vanilla HTML+CSS+ES5-IIFE single-page app (≈3 900 LoC across 11 source files, plus 1 720 LoC across 8 node-based test harnesses) that loads directly from disk with `file://` and ships zero runtime dependencies. It implements all 76 stories' *visible surfaces* against one frozen seeded business day (`App.TODAY = '2026-09-07'`, 15 orders, 6 products, 8 customers, 6 expenses, 3 dues, 3 suppliers, 1 settlement run with 5 rows, 10 audit entries) using a complete shape of computed-domain methods (`econ`, `summary`, `risk`, `stockOf`, `lowVariants`, `countByStatus`, `variantLabel`, plus the real `parseMessage` for paste capture). State is one mutable `App.state` bag, persistence is *none* (zero localStorage / IndexedDB / sessionStorage anywhere — verified by Grep), routing is `hashchange` + full `app.innerHTML` rebuild on every navigation, and the component model is template-string HTML rendered by a small set of helper functions on `App.ui`. The two token system that matters most for link 2 is the **Role × Capability gate** (three money flags `full`/`price`/`cost` + explicit `roles` array, enforced twice — router-side via `App.canReach` and screen-side via `roleLock()` and per-screen guards) and the **Recognition-Basis** invariant (`App.RECOGNITION = {EARNED, REALIZED}`, surfaced via `basisPill` and `completeness` on every money figure; `truth.js` restates the spec inline rather than importing from data.js precisely so a flip or drop is caught). The 8-harness test layout (smoke, auth-zero, truth, flows, classes, contrast, story-coverage, shot/measure over real-Chrome CDP) is an unusually disciplined mutual-blindness design documented at `prototype/tests/README.md` line 8 and architecturally worth preserving. **The biggest tech-debt / architecture smells the architect must absorb as design constraints** are: (1) **no persistence layer at all** — there is no schema, no migration, no storage abstraction, only a seed; the 76 stories in `_bmad-output/.../screen-map.js` describe a far more sophisticated system (tenant isolation, capability-gate, inventory movement ledger, recovery-code five-step overwrite) that the prototype does not begin to cover; (2) ES5/ES2015+ inconsistency — `screens-journeys.js` is the only file using `const`/arrow functions/`Object.assign`, every other module is strict ES5; (3) a hand-maintained 75-row `App.SCREEN_INDEX` magic-string in `app.js` lines 106–181 that must stay in sync with both registered `App.screens.*` keys and the mockup `SMARTBIZ_SCREEN_MAP` (the chrome dropdown has a hand-coded nearest-match scorer at lines 192–218 because sub-routes like `order/ORD-1035` aren't listed by name); (4) hard-coded macOS Chrome binary path in `shot.js` line 10 and `measure.js` line 6 (will not run on Linux/Windows); (5) `App.state` is a free-form mutable bag with no schema (tests reach in directly); (6) the frozen `App.TODAY` clock is deliberate for seed-arithmetic but architect must decide whether production freezes TODAY or replaces with `new Date()`; (7) zero linting / zero CI / zero type annotations / no `package.json` at `prototype/`. **Positive findings to preserve**: there is no console.log / TODO / FIXME / dead code anywhere in `prototype/js/` or `prototype/css/` (Grep confirmed); every module carries a leading block comment explaining its role and the rationale for non-obvious code; in-file comments document decisions rather than syntax; and the test discipline of "mutate before trusting" is unusual and load-bearing.
